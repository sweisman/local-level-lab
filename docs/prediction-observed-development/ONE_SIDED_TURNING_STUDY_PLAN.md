# Two generated turning fits under the candidate stability check

The [one-sided numerical rule](ONE_SIDED_STOPPING_PLAN.md) passed its
deterministic software controls. This study tests it in the complete native
generated turning pipeline without changing the original four-case study.

Reconstruct the two original generated turning inputs and verify the sealed
parent's noise, receiver, prefix, operator and source hashes. Use the same
generating rotating-globe candidate, zero start, 26 nuisance columns,
calibration bounds, clock and structured error objective. The only method
change is the **versioned final stability check**: projected stationarity,
fresh exact repeat, no detectable cost-lowering move across the bounded
full correction and six fixed fractions, and the original physical-position
limits. Save the original full-correction check alongside it. A passing new
fit never relabels either old failure.

Two tasks, one start each, at most 200 native tangent evaluations per task,
two one-thread workers and a 20-minute cooperative wall limit. The allowance
reserves one final base evaluation plus eight stability evaluations; the
optimizer receives the remainder. Every native
call, packet visit and generated draw is charged before execution. Freeze
source, environment, recipe, parent completion and fit hashes, task identities
and limits; require source and task-level reboot-recovery qualification before
launch. Completed failures stay failed.

Success here means technical convergence on both generated turning cases
under the new local rule. It does not establish global optimality, physical
calibration recovery, aircraft error-law coverage or an Earth-model decision.
If it passes, the next control must apply the same rule to all three physical
candidates and the straight/turning geometry matrix before any observed
confirmation is considered.
